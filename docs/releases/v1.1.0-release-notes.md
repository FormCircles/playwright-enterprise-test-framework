# PETF v1.1.0 — Release Notes

**Status:** DRAFT — NOT RELEASED

**Release date:** Pending approval

## Overview

PETF v1.1.0 strengthens the framework's configuration,
fixture architecture, diagnostics, artifact handling,
execution compatibility, and consumer migration guidance.

This release builds on PETF v1.0.0.

The release remains subject to PETF-65 approval.

## Key Improvements

### Configuration

- Deterministic configuration precedence.
- Explicit command-line BASE_URL overrides.
- Environment-specific configuration.
- URL validation and CI target restrictions.

### Fixture Architecture

- Clearer separation of framework and product fixtures.
- Generic API request context lifecycle management.
- Reusable API client and configuration fixtures.
- Consumer-owned product services and Page Objects.

### Failure Diagnostics

- Improved screenshot artifact organization.
- Worker-aware diagnostic paths.
- Trace activation and retention policies.
- Failure evidence preservation.

### CI and Artifact Publication

- Run-scoped artifact collection.
- JUnit and HTML report preservation.
- Screenshot, trace, and diagnostic collection.
- Security verification before artifact publication.
- Explicit 14-day CI artifact retention configuration.
- Container execution and publication workflow improvements.

### Execution Compatibility

Verified execution scenarios include:

- Local serial execution.
- Docker smoke and API suites.
- GitHub Actions CI.
- Experimental two-worker API regression execution.

Parallel UI execution is not approved.

## Migration Guidance

Consumers upgrading from v1.0.0 should review:

`docs/migration/petf-v1.1-consumer-compatibility.md`

Important migration areas include:

- BASE_URL precedence.
- Framework versus product fixture ownership.
- Consumer-owned services and Page Objects.
- Trace configuration.
- Artifact output and publication behavior.

Consumers should pin PETF versions and validate their
own suites before upgrading.

## Known Limitations

### External Consumer Integration

Independent consumer suites currently lack a documented,
reusable pytest integration registration mechanism.

A reusable integration mechanism is proposed for v1.2.0.

### Parallel Execution

Only the verified experimental API subset has been tested
with two workers.

Unrestricted parallel execution and parallel UI tests
are not approved.

### Artifact Security

Security detection is pattern-based.

Screenshot pixel contents are not independently inspected
for embedded secrets.

Consumers must avoid placing sensitive information in
diagnostic artifacts.

### Failed-Run Artifact Publication

Collector behavior has automated test coverage.

Successful hosted artifact publication following an
actual failed test run has not been directly observed.

### Container Image Provenance

The release-commit container publication workflow passed.

Independent remote manifest verification has not been
completed.

### Artifact Retention

GitHub Actions configures 14-day artifact retention.

Actual expiration after 14 days has not yet been observed.

### Canonical Artifact Producers

Some producers still write to legacy output locations.

The collector stages those outputs into the canonical
run-scoped publication directory.

### Optional Interrupt Probe

The full regression includes one intentionally skipped
interrupt probe requiring explicit opt-in.

## Compatibility Statement

PETF v1.1.0 includes migration documentation and
successful framework regression evidence.

Compatibility with every external consumer has not
been independently established.

No claim of zero undocumented breaking changes
is made by these draft release notes.
