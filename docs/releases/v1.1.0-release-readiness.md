## 6. Risk and Exception Register

All exceptions below are PROPOSED.

They are not approved merely because they appear
in this document.

### R-01 — Consumer Integration Registration

**Status:** EXCEPTION PENDING

Consumer composition tests passed.

However, independently hosted consumer suites
do not yet have a documented, reusable pytest
integration registration mechanism.

**Proposed disposition:**

Defer reusable pytest integration to PETF v1.2.0.

Require QA and PM acceptance of the v1.1.0
consumer integration limitation.

### R-02 — BASE_URL Consistency

**Status:** PASS WITH DOCUMENTED LIMITATION — PROPOSED

PETF Settings correctly resolves:

- local: `http://127.0.0.1:8080`
- docker: `http://fastapi:8080`
- ci: `http://127.0.0.1:8080`

PETF API fixtures and inspected reference UI
tests consume the shared PETF base_url fixture.

pytest-playwright also has an independent
configuration default in pytest.ini.

**Proposed disposition:**

Accept the inspected PETF reference execution paths.

Document that consumers using independent
pytest-playwright URL configuration must ensure
target consistency.

This assessment does not establish every possible
external consumer execution path.

### R-03 — Parallel Execution Scope

**Status:** RESTRICTED SUPPORT — PROPOSED

The two-worker API regression subset passed.

Parallel UI execution, larger worker counts,
and unrestricted parallel suites are not approved.

**Proposed disposition:**

Retain serial execution as the default.

Limit parallel support claims to the verified
experimental API subset.

### R-04 — Screenshot and Trace Security

**Status:** EXCEPTION PENDING

Artifact security checks are pattern-based.

Screenshot pixel contents are not independently
inspected for embedded secrets.

**Proposed disposition:**

Document the limitation and require security
risk acceptance before release.

Do not claim comprehensive secret detection.

### R-05 — Failed-Run Artifact Publication

**Status:** EXCEPTION PENDING

Nine collector tests passed.

The collector preserves diagnostic evidence
and rejects unsafe staged artifacts.

Hosted workflows are configured to attempt
collection after unsuccessful test execution,
subject to workflow conditions.

An actual failed hosted test run followed by
successful artifact publication has not been
directly observed.

**Proposed disposition:**

Accept focused collector tests and workflow
configuration as supporting evidence, subject
to QA and DevOps approval.

### R-06 — Full Regression Coverage

**Status:** VERIFIED FOR EXECUTED SUITE

Full local regression completed:

333 passed, 1 skipped.

The opt-in interrupt probe was not executed.

**Proposed disposition:**

Accept the full executed suite and separately
record the intentional interrupt-probe skip.

### R-07 — Artifact Retention

**Status:** OPERATIONAL FOLLOW-UP — PROPOSED

GitHub Actions workflows configure:

`retention-days: 14`

Actual expiration after 14 days has not
been observed.

**Proposed disposition:**

Verify expiration operationally after release
without claiming the expiration event has
already occurred.

### R-08 — Canonical Artifact Producer Migration

**Status:** SCOPE DECISION PENDING

The collector stages legacy output locations
into the canonical run-scoped publication
directory.

Migration of every artifact producer to
native canonical paths remains incomplete.

**Proposed disposition:**

Require explicit approval of the v1.1.0
producer-migration scope.

### R-09 — Published Image Provenance

**Status:** EXCEPTION PENDING

The release-commit container publication
workflow succeeded.

Independent remote manifest verification
was unavailable in the development VM.

The published-container workflow also uses
a mutable latest image reference.

**Proposed disposition:**

Require DevOps review of available GitHub
Actions publication evidence and explicit
acceptance or additional provenance
verification.
